Project scope

Hermes — an AI executive assistant for a multi-business portfolio

Hermes is a Claude-powered assistant that reads and acts across the connected accounts of six separate businesses — email, calendar, files, accounting, messaging, meetings, and notes — either when asked in chat, or automatically on a schedule.

Who it's for

One assistant, six businesses, kept strictly separate

Hermes was built for a founder running a real, varied portfolio — property, farming, commodities, a spa, and personal life — who needed one assistant instead of six disconnected inboxes and apps. Every conversation is locked to a single business (or explicitly widened to "All Businesses"), and each business connects to its own accounts through its own credentials, so information never leaks across entities.

Reach

Every system it can act on

Hermes doesn't just chat — it connects to each business's real accounts through a gateway called Maton, which securely holds OAuth access and lets Hermes call each app's actual API. A business without a connected account gets a clear "not connected" message rather than silently borrowing another business's data.

Interface

Dashboard — seven tabs

A single web dashboard is how the owner actually uses Hermes day to day. No separate app per business — one interface, scoped by whichever business is currently selected.

1AI Agent

  • Free-form chat with the assistant, scoped to one business or all of them
  • Voice mode — record a question, get a spoken reply back
  • Jarvis voice mode — a real-time, phone-call-style voice assistant: no push-to-talk, you just talk and it talks back, and can be interrupted mid-sentence. Hard-locked to read-only in code, so it can summarize and answer but never send, create, edit, or delete anything. In development on a separate feature branch, not yet part of the live app.
  • Upload a file once and reference it across an entire conversation
  • Reads floor plans and floormaps — upload one and the assistant extracts its contents (rooms, layout, assignments) into a clean, structured table, using the same document-extraction engine as the bills pipeline
  • Its own email address — the assistant can send task-completion updates and reports directly to the founder from a dedicated address, rather than only replying inside the chat window
  • Conversation history — reopen or delete any past chat
  • Sees exactly which tools/apps the assistant used to answer, per reply
  • Remembers durable facts about the business over time, automatically

2Billing & Invoices

  • Upload a bill or invoice — vendor, amount, due date, and category are extracted automatically
  • Edit any field by hand, or delete a bill entirely
  • Portfolio-wide billing insights view
  • Proactively scans a business's Gmail/Drive for new bills
  • Automatically detects payment-confirmation emails and marks matching bills paid

3Meeting Copilot

  • Live guidance bullets during a meeting — flags risks, unasked questions, dependencies, next steps, and relevant data, grounded in real business context, never generic
  • Comprehensive mode pulls from five sources at once: strategy, team, known risks, decision history, and indexed records
  • Upcoming-meetings view annotated with prep status
  • Generates a pre-meeting brief before a scheduled call
  • Auto-generates a post-meeting summary and links the recording

4Business Context

  • The knowledge base — upload documents that Hermes can search and reason over per business
  • A document can also be marked visible to every business at once
  • Sensitivity levels (public / internal / confidential / restricted) gate what shows up in search
  • Review and delete the memories Hermes has extracted from past conversations

5Scheduled Tasks

  • Recurring, unattended runs of the same assistant — "every morning, brief me on the farm"
  • Create a task from the UI, or just ask Hermes in chat to set one up
  • Full run history per task — what it did, and what tools it used
  • See Automation below for the full picture

6File Explorer

  • Browse every file the system has touched — uploaded knowledge, generated reports, Drive reads, WhatsApp media — as one searchable tree

7Jobs

  • Code-driven scheduled work, distinct from agent-driven Scheduled Tasks
  • Currently runs a Google reviews intelligence job — gathers and scores reviews of the spa business across regions, publishing a daily report
  • Each job can be started or stopped on demand, with full run history

Unattended work

Automation — Hermes running itself

Before this existed, everything Hermes did was "pull" — someone had to open the app and ask. A lot of the real work is recurring and predictable, so Hermes can now be told once and it keeps doing it.

a chosen business+ a set of apps+ a prompt+ a schedule→ runs itself, unattended

Schedules can be daily, weekdays only, specific weekly days, or hourly. A task can also be created just by asking in chat — "every morning at 7, give me a farm briefing from AFK Gmail and Calendar" is enough; Hermes infers the rest and confirms anything ambiguous.

Autonomy — the unattended safety ceiling

Since nobody is present to approve an unattended action, each task is capped at one of three levels:

Read-only (default)

Read, analyze, report, generate a file. Never sends or changes anything.

Draft

The above, plus creating email drafts — never sending them.

Full

May actually send or modify data — an explicit standing authorization, set on purpose.

Guardrails

Safety model

Before any write action — sending an email, changing a QuickBooks record, deleting something — Hermes summarizes exactly what it's about to do and waits for explicit confirmation in chat. Unattended scheduled runs use the autonomy ceiling above as the equivalent protection, since there's no one there to approve in the moment.

Under the hood

What it's built on

Not required reading to use Hermes, but useful context for anyone evaluating or extending it.

Reasoning

Anthropic Claude runs the whole tool-use loop; a faster, cheaper Claude model handles live meeting guidance separately.

App access

Maton acts as the OAuth gateway to every connected business app, keyed per business.

Voice

Speech-to-text (OpenAI Whisper) and text-to-speech via OpenAI, with OpenAI models also serving as the fallback. A Groq provider remains wired in the code but is not used.

Document extraction

NuExtract pulls structured data (vendor, amount, due date) out of bill and invoice PDFs/images.

Database — AWS RDS

Postgres, managed on AWS RDS, is the system of record: users, businesses, chat history, documents, memories, scheduled tasks, and bills.

Semantic search — pgvector

pgvector, living in the same Postgres instance, powers meaning-based search over the knowledge base and extracted memories for the main assistant.

Semantic search — Pinecone

A dedicated vector database used by the background ingestion pipeline that keeps Gmail/Drive/meeting data continuously synced and searchable.

File storage — AWS S3

Stores original file bytes — bills, generated reports, WhatsApp media, Drive reads — behind short-lived, secure links.

Frontend — Next.js

A separately built Next.js application is the dashboard users interact with; it calls the backend purely as a JSON API, so the agentic system underneath can be swapped, scaled, or deployed independently of the interface.

Note: this repository itself ships a lightweight, no-build vanilla-JS dashboard (templates/index.html + static/*.js) served directly by the backend — that's what the earlier dashboard-tab walkthrough in this document describes. The backend is explicitly designed to be headless (see its own README: "there is no UI... deploy it on its own and point any frontend at it"), and the production Next.js frontend consuming it lives in a separate codebase not included in this bundle.

How the per-query cost is built. Claude dominates the bill. Each assistant query runs an agentic loop (up to 12 tool iterations, HERMES_MAX_TOKENS=8000, effort=low). The system prompt + ~15 Maton tool schemas (~6k tokens) are re-sent on every iteration — prompt caching is not currently enabled in the code, so those tokens are billed at full price each pass. A typical tool-using query works out to ≈40k input + ≈2k output tokens ≈ $0.12 on Sonnet 5 (light Q&A ≈ $0.03; heavy multi-tool ≈ $0.30). Enabling Anthropic prompt caching is the single biggest lever — it could cut agent input cost 50–80%.
